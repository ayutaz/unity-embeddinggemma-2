---
name: project-privacy
description: Check this public repository before commits, pushes, PR descriptions, screenshots, or validation artifact publication; detect personal paths, private identities, credentials, and unchecked images.
---

Read `docs/privacy.md` and run the privacy checker from `tools/` with uv. Keep raw findings and original screenshots in ignored local storage; print only rule, repository-relative filename, and line number.

- Before committing, run `uv run --no-project --python 3.13 python -m embeddinggemma_tools.privacy staged --root ..`. Scan the Git index, not only working files. Use the public GitHub handle and GitHub noreply email for commit metadata; check commit messages and co-author trailers too.
- Before pushing, scan all ancestors of every outgoing commit. A clean current file does not make an old private ancestor safe. Never use `--no-verify`, an empty hooksPath, or an allowlist to conceal a finding.
- For `gh pr merge`, explicitly pass `--author-email` with the public GitHub noreply identity. Do not rely on the account's default squash author email. Local commit names must match the public handle in their noreply address. GitHub-generated squash authors may use only the exact owner-selected public `yousan`/account noreply pair under the provider metadata classification documented in `docs/privacy.md`; this grants no general identity or content exception.
- Before a PR, issue, release, or artifact upload, inspect the actual outgoing body/file separately. It may be untracked and outside the commit scan. Use repository-relative or environment-variable paths. Do not copy terminal commands, stack traces, editor title bars, or absolute file-picker paths into public records.
- Review every literal release attachment for both `gh release create` / `new` and later `upload`; notes review alone does not cover inline assets. Unknown flags, missing files and dynamic paths fail closed. Exact model-asset approval never approves binary release notes or other publication routes.
- Keep each workflow artifact upload behind its matching privacy guard. A passing text/filename check does not certify numerical/model binary internals. Reject or privately retain unsafe diagnostics; do not weaken checks to publish a failing test log.
- Inspect every proposed screenshot visually and with OCR, including title bars, panels, filenames and metadata. Prefer synthetic paths and input data when capturing. Unreviewed images fail closed. Add a hash-bound asset review only after both checks, and repeat them whenever image bytes change. Do not alter validation evidence into a fabricated screenshot.
- Relative input fields do not prove a safe rendered screen: results and exception messages can expand them to absolute paths. Inspect successful results and error/recovery states before approving an image. Keep a failing original private; a later software fix and its new-source execution are separate evidence, never a replacement for the original.
- Original numerical fixture binaries have exact SHA256 reviews. Do not generalize those reviews to logs, archives, model weights, recordings, or arbitrary binaries.
- Model release assets need their own exact distribution review in committed `.privacy-reviewed-model-releases.json` and its hash-bound committed receipt. Recheck the actual descriptor/inventory, source provenance, complete object hash and Sentis-description/JSON privacy through `model_release_privacy` at publication. Untracked or modified review files cannot authorize uploads. This approval never allows weights into Git, unreviewed images/archives, private metadata, CPU/GPU claims or an arbitrary binary exception.
- Native regression data has a separate `.privacy-reviewed-native-regressions.json` policy. Only its exact twelve-asset cohort may use `native_regression_release_privacy`: recheck the complete asset hash, selected source, all graph members/CRCs, semantic and non-model member hashes, remaining traces and textual metadata. Numerical buffers are source-bound, not text-privacy certified. This review does not change original numerical gates, authorize other archives or publish models in Git.
- Distribution execution must use its explicit input/audit route. Record the actual clean graph hash separately from the preserved raw generation hash. Keep original reference/audit bytes and tolerances unchanged; old raw loaders must reject clean graph bytes, and old raw auditors must reject distribution provenance. Do not retire a pinned artifact until its required bytes have verified private backups and the replacement's complete fresh regression has passed.
- If a leak is found, stop publication and automated merges, preserve work privately, inspect all refs and commit identities, and remove the data from current files and history. History rewrite/force push requires user authorization; ordinary privacy checking does not grant it. Preserve branch protection, guard remote heads with leases, verify the remote result, and account for GitHub PR/cache copies separately.
- Before deleting hosted workflow runs or artifacts, map all pinned artifact IDs and verify private backups of every required immutable byte, including model graphs. A metadata-only snapshot is not a model/reference backup. Run deletion also removes artifacts and can break acceptance CI. If exact backup verification fails, stop deletion and prepare a provider-support request; never substitute a regenerated model and call it the original.

Git hooks and CI are the enforcement layers. The skill and Codex tool hook supplement them; do not claim hooks are active before installation/runtime verification.

Generated models are not blanket binary exemptions in Actions. The artifact guard
must inspect PT2 archive/member names and textual metadata, and ONNX protobuf
strings with the pinned parser. Missing parsers, unsupported models and private
metadata fail closed. Opaque numerical tensor buffers are not text-privacy
certified. New PT2 producers remove only optional node stack traces before first
serialization; keep original evidence unchanged and audit retained files read-only.
